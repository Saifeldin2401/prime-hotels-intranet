🔐 Authentication & Authorization Flow تدفق المصادقة والتفويض

عندما يسجل المستخدم الدخول، يقوم النظام بـ:
1. التحقق من بيانات الاعتماد عبر Supabase Auth
2. تحميل الملف الشخصي من جدول profiles
3. تحميل الأدوار من جدول user_roles
4. تحميل الفنادق المعينة من user_properties
5. تحميل الأقسام المعينة من user_departments
6. حساب الدور الأساسي (primaryRole) بناءً على أعلى صلاحية

🔄 Promotion/Transfer Lifecycle دورة حياة الترقية/النقل

عملية الترقية أو النقل تمر بالخطوات التالية:
1. موارد بشرية الفندق تستدعي دالة تقديم الطلب
2. إنشاء سجل ترقية/نقل بحالة "معلق"
3. إنشاء طلب في جدول requests
4. الطلب يمر بسير عمل الموافقة
5. عند الموافقة، المشغل يحدث بيانات الموظف
6. إذا كان تاريخ السريان اليوم أو قبله، يتم التطبيق فوراً

Summary الملخص

The ALTUS Hotels Intranet is a multi-tenant, role-based, property-scoped system where:

  1. Identity: Users have profiles + multiple roles + property/department assignments
  2. Authorization: Computed from primaryRole (highest authority) + property/dept scope
  3. Workflows: Generic requests table powers all approval flows
  4. Targeting: Training/docs/announcements target users, departments, properties, or roles
  5. Automation: Database triggers auto-create onboarding, finalize promotions
  6. Security: PostgreSQL RLS enforces access at database level
شبكة فنادق ألتوس الداخلية هي نظام متعدد المستأجرين، قائم على الأدوار، محدد النطاق بالفندق حيث:

1. الهوية: المستخدمون لديهم ملفات شخصية + أدوار متعددة + تعيينات فندق/قسم
2. التفويض: محسوب من الدور الأساسي (أعلى صلاحية) + نطاق الفندق/القسم
3. سير العمل: جدول الطلبات العام يدعم جميع عمليات الموافقة
4. الاستهداف: التدريب/المستندات/الإعلانات تستهدف مستخدمين أو أقسام أو فنادق أو أدوار
5. الأتمتة: مشغلات قاعدة البيانات تنشئ التهيئة تلقائياً وتنهي الترقيات
6. الأمان: RLS في PostgreSQL يفرض الوصول على مستوى قاعدة البيانات
